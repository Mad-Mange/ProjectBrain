# ADR 001: v2 implementation choices and deviations

Status: implemented and runtime-tested on Windows and Docker Desktop, 2026-10-24/25. Codex user-global retrieval passes a real new-project agent session; Copilot and Claude sessions remain unverified.

The locked stack is preserved: .NET 10 / official ModelContextProtocol.AspNetCore 2.3.0, React/TypeScript/Vite, SQLite/FTS5, two Compose services, one hosted scanner. No replacement fake MCP transport or alternative database ships in production.

1. **Shared workflows.** Application contracts are separate; concrete SQLite-backed transactional services live in Infrastructure and are used by both REST and MCP. This keeps invariants in one implementation without introducing a repository abstraction for every table.
2. **Compact persisted model.** Per-file cached extracts live in file_index, components/profile snapshots are JSON on projects/project_revisions, and audit is centralized. These replace separate file_extracts/project_components/project_profiles physical tables while preserving logical provenance and revision snapshots.
3. **Staged scan publication.** Inventory and bounded extracts are published atomically. Durable read checkpoints let incremental retries reuse unchanged work; directory traversal restarts for safe deletion detection. Full audits never reuse a checkpoint as content proof. Large-root throughput remains unbenchmarked.
4. **Rename safety.** File renames retain immutable experiment evidence at the old path and request recheck. Project-relative references remain stable for unambiguous whole-project moves. Ambiguous identities are recorded, not merged.
5. **No automatic semantic promotion.** Deterministic profiles remain drafts. Human-reviewed generated profile text is never overwritten. Current project profiles still update; retrospective agents create new proposals for reusable conclusions.
6. **Explicit conflict resolution.** A new human-only resolve-validation operation selects a reviewed run for the current scope, validates its current hashes and records the rationale without rewriting historical outcomes.
7. **Extra credential separation.** An optional proposal-only agent token supplements the required human token. MCP itself never exposes human decision tools.
8. **Administrative concurrency.** Knowledge, experiments, root toggles and settings use optimistic versions and durable retry receipts. Root registration also deduplicates canonical paths; scan enqueue deduplicates the active job. Internal scan observations do not require client mutation keys.
9. **Conservative extraction.** Narrow Git HEAD/refs reads and scoped build/Library/Saved exceptions are supported. Multiple Unreal manifests sharing one folder retain separate logical identities and explicitly share source evidence. No Git execution, worktree redirect following, binary scene parsing or external enrichment occurs. Ambiguous whole-project moves retain separate identities and review records; a dedicated identity-resolution UI remains future work.
10. **Export/restore.** Authoritative recovery uses online SQLite backup. JSON export is reference data, without a duplicate-safe import/Markdown bundle.
11. **Real runtime evidence.** Dependencies were restored with authorized network access and the npm lockfile generated. The real .NET/SQLite/MCP, frontend, browser and Compose gates pass. Earlier ignored compile-shape experiments are historical only. Vite/Vitest were patched; Microsoft.Data.Sqlite 10.0.10 plus SQLitePCLRaw.bundle_e_sqlite3 3.0.5 supplies SQLite 3.53.4 without the vulnerable old native dependency. NuGet auditing stays enabled. See [upstream SQLitePCLRaw guidance](https://github.com/ericsink/SQLitePCL.raw) and the test log.
12. **Global onboarding is explicit.** The optional Windows setup script backs up user configuration, registers the local MCP endpoint, stores a dedicated agent credential in the user environment, and installs English global instructions. Seven read-only tools work under the client's `writes` approval mode; the two proposals remain writes. A real Codex session in a new empty project passes retrieval/profile checks without project-local configuration or file changes. Copilot/Claude templates and CLI syntax are checked, but their model sessions remain unverified.
